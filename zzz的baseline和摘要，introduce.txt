为什么可以被接受
你这个 baseline 在方法论上属于 controlled ablation（受控消融），是 HCI/VIS 圈完全标准的做法。它的合法性来自一条公理：

若研究问题是"X 是否对 Y 有效"，则 baseline 应该是"除了 X 之外其他都一样"的版本，而不是"完全不同的系统"。

你的研究问题是 "full-duplex affordance 对 intent revision / EDA 是否有效"，所以：

✅ baseline = VerbalVis 关闭 full-duplex（其他全相同）→ 干净隔离 X
❌ baseline = 跑别人的真实系统（DashChat/LightVA）→ 同时变了 model、prompt、tools、UI、dataset，X 被混淆变量淹没

这条逻辑在评审眼里是站得住脚的，而且更"科学"——评审会反过来批评"跑别人系统"的做法，说它无法归因。

学界先例：ablation-as-baseline 是 VIS/CHI 通行做法
这种"用自己的弱化版本作 baseline"的做法在 VA/HCI 圈非常普遍，列几个对照：
论文/做法Baseline 设计Data Formulator 2 (CHI 2025)"DF2 without iteration thread" 作为 ablationLightVA (TVCG 2024)"LightVA without planner agent" 作为 ablation大量 NLI-for-Vis 工作"system without ambiguity widget" 作为对照Talk to the Wall (TVCG 2025)speech-only vs touch-only vs combined（modality ablation）

这一 reframe 让 ablation 成为正确选择，而 system comparison 反而成为错的选择。

LightVA（TVCG 2024, Zhao et al., Fudan）
核心命题
VA 不是"一次性把图画好"，而是分析师根据观察迭代地提出新任务、修订旧任务、最终获得洞察的过程。论文把这个迭代过程交给 LLM agent 来辅助：用户给一个高层目标 + 数据，agent 自动分解任务 → 执行（出图 + 出洞察）→ 评估是否需要进一步分解 → 推荐新任务，循环往复。
架构机制
三个 LLM 模块的递归协作：

Planner：又分 Recommender（把高层目标转成可执行任务）和 Decomposer（把复杂任务拆成子任务）
Executor：拿到任务后，生成 Vega-Lite 可视化代码 + Python 数据建模代码并执行，产出图和洞察
Controller：递归算法，协调 planner 和 executor，决定是否继续分解

latex\subsection{Baseline Design: VerbalVis-TB}
\label{sec:baseline}

To isolate the effect of full-duplex affordance, we construct 
\textbf{VerbalVis-TB}, a turn-based variant of VerbalVis that mirrors 
the interaction regime of representative LLM-agent VA 
systems~\cite{zhao2024lightva,cheng2025dashchat} while controlling 
for model, prompt, tools, dashboard, and dataset.

\textbf{Borrowed regime, controlled implementation.} 
VerbalVis-TB inherits from LightVA the principle of \emph{plan-then-execute}: 
the LLM controller completes its full explanation and tool-call sequence 
before yielding the conversational floor back to the 
user~\cite{zhao2024lightva}. It inherits from DashChat the principle 
of \emph{visible-history dialogue}: a persistent chat panel renders 
both user and system turns as transcribed text, supporting retrospective 
review of past 
exchanges~\cite{cheng2025dashchat}. To prevent confounding from 
implementation differences across systems, we re-instantiate both 
principles \emph{within} the VerbalVis codebase: the underlying 
\texttt{gpt-realtime} model, the three-tool schema 
(\texttt{filter\_data}, \texttt{append\_visual}, \texttt{highlight\_visual}), 
the DuckDB-backed analytics layer, the Olist dataset, and the dashboard 
layout are byte-identical between conditions.

\textbf{Mechanism-level differences.}
Four implementation switches distinguish VerbalVis-TB from VerbalVis:
\begin{itemize}
\item \textbf{Barge-in disabled.} The Realtime session configures 
\texttt{turn\_detection.interrupt\_response = False}; user speech 
detected during system response is buffered rather than triggering 
\texttt{response.cancel}.
\item \textbf{Plan-then-execute dispatch.} Tool calls are batched 
until \texttt{response.done}, then dispatched serially; the dashboard 
context is reinjected once per turn rather than once per tool call.
\item \textbf{Chat panel UI.} A persistent text panel renders both 
sides of the conversation, with a turn-indicator light and a history 
list of executed tool calls, mirroring the visible-state dialogue of 
DashChat.
\item \textbf{Prompt rule.} The system instruction includes an explicit 
turn-taking clause: ``Respond to one user request at a time; complete 
your explanation and tool calls before the user speaks again.''
\end{itemize}

\textbf{Why not benchmark against LightVA or DashChat directly?}
A direct comparison would conflate full-duplex modality with 
differences in tool execution paradigm (LightVA generates Vega-Lite 
and Python code at runtime; DashChat coordinates multiple agents 
over a dashboard-design pattern library), model capability, prompt 
engineering, and target dataset. Such a comparison cannot answer our 
research question, which concerns the effect of full-duplex 
\emph{affordance} on intent revision in EDA. By holding everything 
constant except the four switches above, VerbalVis-TB provides the 
single-variable comparator that this question requires. This design 
follows the modality-isolation tradition exemplified by Molina León 
et al.'s speech-vs-touch ablation on collaborative 
walls~\cite{molinaleon2025talktothewall}.

visual analytics, we construct \textbf{VerbalVis-Cascade}, a 
cascaded-pipeline baseline that mirrors the text-driven, turn-based

that shares VerbalVis's system prompt and tool schema 
(\texttt{filter\_data}, \texttt{append\_visual},

synthesized back to audio via TTS. The dashboard, DuckDB analytics 
layer, and Olist dataset are byte-identical to the VerbalVis

generalization of the text-based interaction regime adopted by 
LightVA's chat view and DashChat's chat panel: a single textual LLM 
reasons over conversation context and dispatches structured tool 
calls between explicit turns. By preserving their canonical 
text-LLM tool-calling stage and only adding a thin ASR/TTS wrapper, 
VerbalVis-Cascade allows us to compare interaction regimes 
(end-to-end full-duplex vs.\ cascaded turn-based) without forcing 
participants to switch modality between conditions.

(\texttt{gpt-realtime}, end-to-end speech) and the baseline 
(\texttt{gpt-4o}, cascaded pipeline) differ in both interaction regime 
and underlying stack, observed differences cannot be attributed to 
full-duplex affordance alone. We therefore complement the user study 
with two analyses: (i) a tool-call sanity-check benchmark 
(Section~\ref{sec:bench}) verifying that 
VerbalVis and VerbalVis-Cascade achieve comparable tool-selection 
accuracy on a controlled set of utterances, isolating capability 
differences from interaction differences; and (ii) a per-stage latency 
breakdown (ASR, LLM, tool dispatch, TTS) reported alongside 
user-perceived outcomes, allowing readers to attribute observed 
effects to specific pipeline stages.

latex\begin{abstract}
Exploratory data analysis (EDA) is fundamentally a process of 
\emph{analytical intent evolution}: analysts continuously revise their 
direction as new observations surface hypotheses, refute them, and 
prompt further questions. Existing speech- and language-driven visual 
analytics systems are uniformly turn-based, confining intent revision 
to discrete handoff points and forcing analysts to passively witness 
explanations that have already deviated from their interest. We argue 
that, in a conversational visual analytics context, \emph{user barge-in 
is not interaction noise but the most directly observable manifestation 
of analytical intent evolution}, and that full-duplex speech models 
make this signal actionable for the first time. We present 
\textbf{VerbalVis}, a hands-free, full-duplex conversational visual 
analytics system built on the GPT-realtime-2 speech-to-speech API and 
a tool-calling LLM controller backed by an in-memory DuckDB analytics 
layer. VerbalVis cancels in-flight responses on speech onset, captures 
the redirecting utterance, and replans against a shared dashboard whose 
state is reinjected as system context after every tool call. We 
contribute (1) an \emph{Intent Evolution} framework identifying three 
recurring revision types --- Goal Shift, Hypothesis Correction, and 
Scope Narrowing --- with their triggering conditions; (2) a 
15-operation tool taxonomy aligned to the Brehmer--Munzner \emph{why} 
and Yi et al.\ \emph{how} axes; (3) the VerbalVis prototype on the 
Olist Brazilian e-commerce dataset; and (4) a within-subjects user 
study ($N=8$) comparing VerbalVis against a cascaded turn-based 
baseline, complemented by a technical benchmark of 250 barge-in trials. 
Results show that full-duplex affordance increases intent-revision 
count, reduces time-to-revision, and improves perceived control without 
elevating cognitive load.

Introduction（约 700 词，5 段）
latex\section{Introduction}
\label{sec:intro}
\IEEEPARstart{E}{xploratory} data analysis (EDA) is an inherently 
iterative process. An analyst glances at a trend, forms a hypothesis, 
queries the data for confirmation; the data refutes the hypothesis; 
the analyst pivots to a related question; that question splinters 
into sub-questions; and so on~\cite{pirolli2005sensemaking, 
kandel2012enterprise}. The \emph{shape} of this trajectory --- where 
the analyst turns, why, and how quickly --- is not incidental; it 
is the substance of sensemaking. Supporting EDA in a conversational 
visual analytics (VA) system therefore means supporting not query 
answering but \emph{analytical intent evolution}: the continuous, 
often mid-utterance revision of analytical direction.

\textbf{The structural limitation of current conversational VA.} 
Representative natural-language interfaces for visualization --- 
DataTone~\cite{gao2015datatone}, Eviza~\cite{setlur2016eviza}, 
NL4DV~\cite{narechania2020nl4dv}, and recent LLM-based systems 
including Data Formulator~2~\cite{wang2025dataformulator2}, 
LightVA~\cite{zhao2024lightva}, and 
DashChat~\cite{cheng2025dashchat} --- all operate in a turn-based 
regime: the user speaks or types, the system processes, the system 
responds, the user speaks again. Intent revision is consequently 
confined to discrete handoff points. When the system is mid-response 
with an analysis that has already deviated from the user's interest, 
the user has no recourse except to wait, then issue a correction, 
then wait again. The cost compounds in voice modalities, where 
responses unfold at speaking rate and a misdirected explanation may 
consume tens of seconds before the user regains the floor.

\textbf{The key observation.} Full-duplex speech-to-speech models 
such as Moshi~\cite{defossez2024moshi} and OpenAI's 
gpt-realtime-2~\cite{openai_gptrealtime_blog, openai_realtime_docs} 
expose a new affordance: the user can interrupt the system at any 
instant, and the system can both detect the interruption and cancel 
its in-flight response within hundreds of milliseconds. The 
community has converged on a shared evaluation vocabulary for 
these capabilities --- pause handling, backchanneling, turn-taking, 
and interruption management --- formalized in the Full-Duplex-Bench 
suite~\cite{lin2025fdbench}. We argue that, in a conversational VA 
context, \emph{this interruption is not noise to suppress but a 
first-class semantic signal}: when an analyst barges in mid-explanation, 
the act itself carries information --- the current analytical 
direction requires revision. We formalize this as the central claim 
of this work: \emph{user barge-in is the most directly observable 
manifestation of analytical intent evolution}, and we design a 
system around it.

\textbf{VerbalVis.} We present \textbf{VerbalVis}, a hands-free, 
full-duplex conversational visual analytics system. We adopt 
\emph{hands-free} in its long-standing HCI 
sense~\cite{sears2003handsfree} --- analytical operations issued 
entirely by voice, without keyboard or pointer input --- and 
\emph{speech interaction} in the sense recently adopted in the 
visualization community~\cite{molinaleon2025talktothewall}. Built 
on gpt-realtime-2 and a tool-calling LLM controller backed by an 
in-memory DuckDB analytics layer, VerbalVis cancels in-flight 
responses on speech onset, captures the redirecting utterance, 
and replans against a shared dashboard whose state is reinjected 
as system context after every tool call. The dashboard thus serves 
not as a passive display but as the continuously synchronized 
substrate that grounds the LLM's reasoning in what the analyst 
currently sees. We instantiate VerbalVis on the Olist Brazilian 
e-commerce dataset, organize its 15 analytical operations along 
the Brehmer--Munzner \emph{why} and Yi et al.\ \emph{how} 
axes~\cite{brehmer2013multi, yi2007toward}, and evaluate it against 
a cascaded turn-based baseline that faithfully instantiates the 
text-LLM-plus-voice-wrapper regime of representative LLM-VA 
systems~\cite{zhao2024lightva, cheng2025dashchat}.

\textbf{Contributions.} We make four contributions:
\begin{enumerate}
\item An \textbf{Intent Evolution framework} that conceptualizes 
intent revision in EDA and identifies three recurring revision 
types --- \emph{Goal Shift}, \emph{Hypothesis Correction}, and 
\emph{Scope Narrowing} --- with their triggering conditions and 
dashboard-level consequences.
\item An \textbf{interruption-triggered cancel-and-replan 
architecture} that moves intent revision from discrete handoff 
points to a continuously available action, with the shared 
dashboard serving as the speech-state bridge.
\item The \textbf{VerbalVis system}: a prototype implementation 
with a 15-operation tool taxonomy of which six representative 
operations are realized end-to-end on a DuckDB-backed Olist 
e-commerce dashboard.
\item A \textbf{within-subjects user study ($N=8$)} comparing 
VerbalVis against a cascaded turn-based baseline along 
intent-revision count, time-to-revision, exploration breadth, 
and perceived control, complemented by a 250-trial automated 
technical benchmark isolating the mechanism-level effect of 
barge-in handling.
\end{enumerate}

现有系统怎么对待打断？

阶段默认处理TTS 播放中用户开口停止 TTS 播放（"cancel"）后续把用户新说的话当作下一轮的输入，继续走 ASR → LLM 流程

第三层：为什么 barge-in 携带 "semantic" 信息？
这是 thesis 中最容易被攻击的一步。需要严密论证：barge-in 的发生本身，独立于打断后说的话，已经携带语义信息。
论证 1：打断的发生时机本身就是信息
用户打断时机携带的语义系统刚开口 0.5 秒用户对系统的方向不满（早期打断 = 方向修订）系统说到一半用户对系统的论证不满（中期打断 = 假设修订）系统快说完时用户对系统的结论不满（晚期打断 = 结论修订）
只要系统记录"何时被打断"，就能推断出用户是在反对方向、论证、还是结论。这就是 timing 携带的语义。
论证 2：打断 vs 等系统说完再说，是两种不同的认知行为
行为认知状态用户等系统说完再说（turn-taking）用户接受了系统的当前方向，只是想接着补充/追问/确认用户打断系统说话（barge-in）用户已经判断当前方向偏了，必须立刻干预
这两种行为的认知前提不一样。等说完意味着"我同意你说的方向，但有补充"；打断意味着"你正在走错方向，停下"。
这是 barge-in 携带的语义的核心：它不仅传递"我要说话"，还传递"当前的分析方向需要修订"。
论证 3：从沟通学（Conversation Analysis）找理论支撑
社会语言学和沟通研究里早就有这个区分。Sacks et al. 1974 的 turn-taking 理论里，把交流中的发言权交接分成两类：

Smooth transition：一方说完，另一方接着说（正常轮次）
Interruption：一方打断另一方（标记性事件）

Conversation Analysis 文献里反复证明，interruption 在对话中是一种 marked phenomenon——即它"标记"了说话人对当前内容的不接受、不耐烦、急于纠正、急于澄清等态度。
也就是说，人类语言学已经承认"打断"是携带语义的事件，不只是声学事件。VerbalVis 只是把这个语言学事实操作化进 VA 系统。

第五层：判断的理由总结
回到你的原问题"判断理由是什么"——答案是三段论：
大前提（来自语言学）

Barge-in（打断）在人类对话中本就携带语义信息——它标记说话人对当前内容的非接受态度，并隐含修订请求。这是 Conversation Analysis 几十年来的稳定结论。

小前提（来自 EDA 理论）

在 EDA 中，分析师对系统当前方向的非接受态度即是"intent revision"。这与 Pirolli-Card sensemaking loop 中的"foraging-to-reasoning 切换"和 Kandel et al. 实证观察到的"反复重构问题"是同一现象。

因此，在 conversational VA 中，barge-in 不是噪声，而是 intent evolution 的最直接、最可观测的行为足迹。把它当作 first-class semantic signal 处理——即被命名、传递、操作——是 conversational VA 的正确架构方向。

Introduction（5 段，约 720 词）
latex\section{Introduction}
\label{sec:intro}
\IEEEPARstart{E}{xploratory} data analysis (EDA) is an inherently 
iterative process. An analyst glances at a trend, forms a hypothesis, 
queries the data for confirmation; the data refutes the hypothesis; 
the analyst pivots to a related question; that question splinters 
into sub-questions; and so on~\cite{pirolli2005sensemaking, 
kandel2012enterprise}. The \emph{shape} of this trajectory --- 
where the analyst turns, why, and how quickly --- is not 
incidental; it is the substance of sensemaking. Supporting EDA 
in a conversational VA system therefore means supporting not 
query answering but \emph{analytical intent evolution}: the 
continuous, often mid-utterance revision of analytical direction.

\textbf{The structural limitation of current conversational VA.} 
Representative natural-language interfaces for visualization --- 
DataTone~\cite{gao2015datatone}, Eviza~\cite{setlur2016eviza}, 
NL4DV~\cite{narechania2020nl4dv}, and recent LLM-based systems 
including Data Formulator~2~\cite{wang2025dataformulator2}, 
LightVA~\cite{zhao2024lightva}, and 
DashChat~\cite{cheng2025dashchat} --- all operate in a turn-based 
regime: the user speaks or types, the system processes, the system 
responds, the user speaks again. Intent revision is consequently 
confined to discrete handoff points. When the system is 
mid-response with an analysis that has already deviated from the 
user's interest, the user has no recourse except to wait, then 
issue a correction, then wait again. The cost compounds in voice 
modalities, where responses unfold at speaking rate and a 
misdirected explanation may consume tens of seconds before the 
user regains the floor.

\textbf{The key observation.} Full-duplex speech-to-speech models 
such as Moshi~\cite{defossez2024moshi} and OpenAI's 
gpt-realtime-2~\cite{openai_gptrealtime_blog, openai_realtime_docs} 
expose a new affordance: the user can interrupt the system at any 
instant, the system both detects the interruption and cancels its 
in-flight response within hundreds of milliseconds, and --- 
crucially for our purposes --- the model natively \emph{truncates} 
the interrupted assistant turn in the conversation history, 
preserving the fact that the previous response was cut 
short~\cite{openai_realtime_docs}. The subsequent generation thus 
takes place in the presence of a structurally marked interruption 
event. We argue that, in a conversational VA context, 
\emph{this structural mark carries semantic content about 
analytical intent revision}: when an analyst barges in 
mid-explanation, the act itself indicates that the current 
analytical direction requires modification, and the truncated 
history together with the redirecting utterance jointly encode 
\emph{what} the modification is. The community has converged on 
a shared evaluation vocabulary for full-duplex 
behavior --- pause handling, backchanneling, turn-taking, and 
interruption management --- formalized in the Full-Duplex-Bench 
suite~\cite{lin2025fdbench}, but this vocabulary has so far 
addressed conversational naturalness rather than what an 
interruption \emph{means} in an analytical workflow.

\textbf{VerbalVis.} We present \textbf{VerbalVis}, a hands-free, 
full-duplex conversational VA system. We adopt \emph{hands-free} 
in its long-standing HCI sense~\cite{sears2003handsfree} --- 
analytical operations issued entirely by voice, without keyboard 
or pointer input --- and \emph{speech interaction} in the sense 
recently adopted in the visualization community by 
Molina Le\'on et al.~\cite{molinaleon2025talktothewall}. The 
contribution of VerbalVis is not a new mechanism for handling 
barge-in at the model level; it is an architectural integration 
that, to our knowledge, has not previously been instantiated in 
visual analytics. VerbalVis combines (i) the native barge-in 
handling of gpt-realtime-2, including server-side voice activity 
detection, in-flight response cancellation, and history truncation; 
(ii) a tool-calling LLM controller that dispatches a 
fifteen-operation analytical taxonomy aligned to the 
Brehmer--Munzner \emph{why} and Yi et al.\ \emph{how} 
axes~\cite{brehmer2013multi, yi2007toward}, executed against an 
in-memory DuckDB layer; and (iii) a continuously reinjected 
dashboard context that, after every tool call, surfaces the 
current visual state back into the system prompt so that 
post-interruption replanning is grounded in what the analyst 
actually sees. Prior LLM-agent VA systems achieve subsets of 
this combination: LightVA~\cite{zhao2024lightva} provides 
agentic tool execution but generates code at runtime, incurring 
multi-second latencies incompatible with synchronous interruption; 
DashChat~\cite{cheng2025dashchat} provides conversational LLM 
coordination but for dashboard authoring rather than analytical 
use. VerbalVis is, to our knowledge, the first system to combine 
all three primitives within a single VA pipeline.

\textbf{Contributions.} We make four contributions:
\begin{enumerate}
\item An \textbf{Intent Evolution framework} that conceptualizes 
intent revision in EDA and identifies three recurring revision 
types observed in conversational analytical sessions --- 
\emph{Goal Shift}, \emph{Hypothesis Correction}, and \emph{Scope 
Narrowing} --- with their triggering conditions and 
dashboard-level consequences. These types are conceptual 
categories used to organize observation; the system treats them 
with uniform downstream processing rather than per-type runtime 
dispatch.
\item An \textbf{architectural integration} of three existing 
primitives --- native barge-in handling, schema-based tool 
calling, and continuously reinjected dashboard context --- that 
enables intent revision to move from discrete handoff points to 
a continuously available action without introducing new 
model-level mechanisms.
\item The \textbf{VerbalVis system}: a prototype implementation 
with a 15-operation tool taxonomy, of which six representative 
operations are realized end-to-end on a DuckDB-backed Olist 
e-commerce dashboard.
\item A \textbf{within-subjects user study ($N=8$)} comparing 
VerbalVis against a cascaded turn-based baseline along 
intent-revision count, time-to-revision, exploration breadth, 
and perceived control, complemented by a 250-trial automated 
technical benchmark isolating the system-level effect of 
barge-in handling.
\end{enumerate}

The remainder of the paper is organized as follows. 
Section~\ref{sec:related} positions our work relative to NLI for 
visualization, LLM-agent VA, sensemaking theory, and full-duplex 
conversational AI. Section~\ref{sec:framework} introduces the 
Intent Evolution framework. Section~\ref{sec:system} describes 
the design and implementation of VerbalVis. 
Section~\ref{sec:case} reports a case study illustrating all 
three revision types in a single session; 
Section~\ref{sec:study} reports the user study and technical 
benchmark. Sections~\ref{sec:discussion}--\ref{sec:conclusion} 
discuss limitations and conclude.
