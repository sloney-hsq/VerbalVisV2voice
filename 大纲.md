下面这套大纲与现在确定的标题、Abstract、Introduction 和系统设计完全对应：

# VerbalVis: Full-Duplex Conversational Visual Analytics for Analytical Intent Revision

整篇论文只讲一条主线：

[
\text{Visual Observation}
\rightarrow
\text{Analytical Intent Revision}
\rightarrow
\text{Full-Duplex Expression}
\rightarrow
\text{Tool Execution}
\rightarrow
\text{Updated Dashboard}
]

其中：

* 可视化帮助用户发现趋势、差异、异常和反预期现象；
* 全双工语音让用户立即表达新的分析方向；
* 分析规划模块理解新的请求；
* Tool layer 将请求落实成数据与可视化操作；
* 状态协调模块防止旧语音和旧工具结果继续影响 Dashboard；
* 更新后的 Dashboard 支持下一轮观察。

五层结构应被表述为 **功能职责** ，不必声称它们是五个完全独立的软件服务。你上传的版本已经明确了这一点，也明确了 stale result、turn epoch 和 latest committed dashboard state 的作用。

# 1. Introduction

```latex
\section{Introduction}
\label{sec:intro}
```

## 本节目标

回答六个问题：

1. EDA 为什么会改变方向？
2. 可视化为什么不是语音系统的附属输出？
3. 为什么 turn-based conversation 不够？
4. Full-duplex conversation 增加了什么能力？
5. 为什么停止音频仍然不够？
6. VerbalVis 具体做了什么？

## 推荐段落结构

### Paragraph 1：EDA 中的方向变化

说明 EDA 不是固定步骤：

* 用户观察数据；
* 发现趋势、差异、异常或反预期现象；
* 改变当前问题、暂时解释或数据范围。

定义：

> Analytical intent revision refers to a material change to an ongoing analytical question, tentative explanation, or data scope.

### Paragraph 2：为什么必须有可视化

说明纯语音系统的限制：

* 信息顺序由 Assistant 决定；
* 语音信息短暂存在；
* 跨类别和跨时间比较困难；
* 用户可能无法发现 Assistant 未提及的现象。

说明 Dashboard 的作用：

* 同时外化多个数据关系；
* 支持比较、验证和异常发现；
* 保持当前分析状态；
* 触发下一步分析请求。

### Paragraph 3：语音与可视化互补

明确：

* visualization supports observation, comparison, and verification；
* speech supports expression and revision；
* tools operationalize the request；
* dashboard presents the result and supports continued exploration。

### Paragraph 4：现有 conversational VA 的局限

介绍：

* NL interfaces；
* multimodal VA；
* LLM-powered VA；
* agentic analysis。

指出共同局限：

> 用户通常在系统完成当前 response 后才能继续修改分析。

### Paragraph 5：Turn-based delay

重点不是“用户永远不能修改”，而是：

> 用户已经决定改变方向，但系统仍在说话或执行旧操作。

### Paragraph 6：Full-duplex conversation

说明：

* 系统说话时仍然监听；
* 用户无需使用单独的 stop command；
* 打断 utterance 可以同时停止旧解释并表达新方向。

### Paragraph 7：为什么 speech-level barge-in 不够

区分：

* acknowledgement；
* ASR repair；
* clarification；
* stop request；
* analytical revision。

同时说明：

* 停止音频不等于停止工具；
* 旧结果可能继续更新 Dashboard。

### Paragraph 8：选择性保留与取消

说明系统既不能：

* 保留所有旧工作；

也不能：

* 每次打断就重置全部状态。

它需要：

* 取消未完成且已过时的工作；
* 保留已经提交且仍相关的 filters、views 和 findings。

### Paragraph 9：VerbalVis overview

简洁介绍五个功能层：

1. full-duplex interaction；
2. analysis planning；
3. analytical tools；
4. visualization state；
5. coordination and state management。

不要在 Introduction 中逐一展开实现细节。

### Paragraph 10：Formative inquiry

介绍：

* 4 participants；
* 目的不是建立通用 taxonomy；
* 用 Goal、Working Hypothesis、Scope 描述 revision；
* 这些类别 overlapping、non-exhaustive、not runtime classes。

### Paragraph 11：Main study

介绍：

* 8 participants；
* within-subjects；
* Full-Duplex vs Turn-Based；
* open-ended EDA；
* 评价 responsiveness、control、flow、state understanding、workload、behavior 和 outcomes。

### Contributions

保持三项：

1. formative findings and design requirements；
2. VerbalVis system；
3. exploratory within-subjects evaluation。

## 2.3 Full-Duplex Speech and Interruption

```latex
\subsection{Full-Duplex Speech and Interruption}
\label{sec:rw-duplex}
```

### 应写内容

先区分：

* push-to-talk；
* half-duplex；
* streaming；
* full-duplex。

再区分：

* overlap；
* backchannel；
* floor-taking；
* barge-in；
* accidental noise。

讨论：

* turn-taking models；
* barge-in detection；
* low-latency speech models；
* Moshi；
* Duplex Conversation；
* SyncLLM；
* SALMONN-omni；
* semantic VAD。

### 重点说明

Full-duplex model 主要解决：

* 同时听和说；
* 低延迟；
* overlap processing；
* audio interruption。

但它本身不一定解决：

* 用户的分析语义；
* 工具取消；
* 数据查询取消；
* Dashboard 状态一致性。

### 本节结尾差距

> Full-duplex speech enables users to interrupt an ongoing response, but speech-level interruption does not by itself determine whether the analytical direction has changed or whether response-dependent analytical actions remain valid.

## 3.3 Revision Constructs and Coding Boundaries

```latex
\subsection{Revision Constructs and Coding Boundaries}
```

### 定义三种 revision

#### Analytical Goal Shift

改变主要分析问题或希望获得的知识结果。

#### Working-Hypothesis Revision

修改、否定或限定一个已经存在的暂时解释。

#### Analytical Scope Refinement

改变相关数据的：

* population；
* time；
* geography；
* category；
* variable；
* granularity。

### 定义 analytical revision episode

必须同时满足：

1. utterance 之前存在可识别的 active analytical direction；
2. 新 utterance 实质性改变、限定或替代它。

### 边界代码

不应自动算作 revision：

* initial question formation；
* initial hypothesis formation；
* ASR correction；
* clarification；
* backchannel；
* simple stop；
* chart representation change；
* metric or method change。

除非这些行为同时改变了分析目标、解释或数据范围。

## 3.6 Design Requirements

```latex
\subsection{Design Requirements}
```

推荐最终用五条。

### DR1: Ground interpretation in the current visual and conversational state

新请求必须基于：

* current filters；
* visualizations；
* highlights；
* current dialogue；
* current analytical direction。

### DR2: Allow immediate revision without requiring a separate stop action

用户应能在 Assistant 说话时直接表达新请求。

一个 utterance 可以产生多个结构化操作。

停止不仅作用于音频，也作用于：

* pending tool calls；
* running tasks where possible；
* late results；
* pending Dashboard commits。

### DR5: Communicate the active request and current analytical state

界面应显示：

* listening/speaking/executing；
* active filters；
* recent tool actions；
* whether interruption was accepted；
* whether Dashboard has been updated。

## 4.4 Selective State Preservation

```latex
\subsection{Selective State Preservation}
```

解释三类状态：

### Committed and still valid

保留：

* 已应用且仍相关的 filter；
* 已生成的图表；
* 当前分析结果。

### Pending and response-dependent

取消或拒绝：

* 尚未提交的旧 filter；
* 旧图表更新；
* 旧解释的迟到结果。

### Explicitly replaced by the user

删除或修改：

* 用户明确移除的 filter；
* 用户明确替换的图表；
* 用户明确改变的分析范围。

# 9. Discussion

```latex
\section{Discussion}
\label{sec:discussion}
```

---

## 9.1 Full-Duplex Conversation in Visual Analysis

讨论：

* full-duplex 的价值不是简单提高语速；
* 它减少 revision 已经发生但尚未表达的等待；
* 对长解释和多步工具执行更有价值；
* 对简单单步问题价值可能有限。

---

## 9.2 Why Visualization Is Essential

明确回答：

> 为什么不是纯语音系统？

讨论：

* charts expose patterns not selected by Assistant；
* multiple values persist simultaneously；
* users can verify spoken claims；
* Dashboard supports comparison and memory；
* visual observation generates subsequent questions。

形成闭环：

[
\text{see}
\rightarrow
\text{revise}
\rightarrow
\text{speak}
\rightarrow
\text{act}
\rightarrow
\text{see again}
]

---

## 9.3 Barge-in Is Not Equivalent to Revision

讨论：

* overlap is temporal；
* revision is semantic；
* repair、acknowledgement、clarification 不应都造成 full reset；
* 系统需要在即时响应与错误取消之间平衡。

---

## 9.4 Cancellation and State Preservation

讨论：

* speech cancellation；
* tool invalidation；
* stale-result rejection；
* committed-state preservation；
* undo and recovery；
* transaction-like semantics for interactive agents。

这里可以讨论其他带共享界面的 agent 系统，但不要扩大成未经验证的通用理论。

---

## 9.5 Design Implications

给出 4–5 条可迁移建议：

1. Keep listening during long spoken or analytical responses；
2. Interpret overlap using task and interface context；
3. Bind actions to the response that initiated them；
4. Separate pending work from committed visual state；
5. Make the active request and state transitions visible。

---

## 9.6 Implications for Future Conversational VA

讨论未来：

* richer tool sets；
* direct manipulation + speech；
* provenance and branching；
* user-controlled cancellation；
* partial result streaming；
* confidence and ambiguity；
* professional datasets；
* collaborative analysis。

## 最重要的章节边界

为了避免后面再次变得混乱，固定下面的分工：

* **Introduction** ：为什么要研究；
* **Related Work** ：别人做到了什么、缺什么；
* **Formative Inquiry** ：用户行为给出了什么设计需求；
* **VerbalVis Design** ：系统应该如何支持这些需求；
* **Implementation** ：系统具体如何实现；
* **Usage Scenario** ：系统能力如何在连续分析中体现；
* **User Study** ：如何评价；
* **Results** ：观察到了什么；
* **Discussion** ：这些结果意味着什么。

尤其不要再把下面内容放进 Introduction：

* 具体 event name；
* tool parameter normalization；
* turn epoch 伪代码；
* frontend synchronization；
  -完整五层逐段实现。

这些全部放到 Design 和 Implementation，Introduction 只保留一段五层概览。
